# ADR 0001: スラッシュコマンドを /knowledge にし、/kb を廃止する

- 状態: 承認
- 日付: 2026-10-18
- 対象: Pi と OpenCode のスラッシュコマンド `/kb`

## 背景

- pi-plugins の共通規約（[docs/plugin-conventions.md](../../../docs/plugin-conventions.md)）は、スラッシュコマンドを `pi-` を除いたパッケージ名にする。このパッケージの名前は `knowledge` である。
- 現状の `/kb` は、CLI の `kb` と同じ語を使う。利用者は、シェルの `kb lint` と Pi の `/kb lint` を同じものとして覚えている。
- CLI の `kb` は、CI（`kb lint`）と、エージェントが bash から呼ぶ `kb note` などで使われている。

## 決定

1. スラッシュコマンドを `/knowledge` にする。Pi と OpenCode の両方で同じ名前にする。
2. `/kb` は別名として残さない。
3. CLI の bin 名 `kb` は変えない。
4. README・DESIGN.md・AGENTS.md・スキルの、スラッシュコマンドの表記を `/knowledge` に揃える。

## 理由

- 規約に従い、スラッシュコマンドの名前をパッケージ名から決める。
- スラッシュコマンドと CLI の名前を分けることで、CI と bash の既存の呼び出し（`kb lint`、`kb note` など）を変えずに済む。
- 表面（コマンド）は1つだけと `test/contract/surface.test.ts` が固定している。別名を残すと表面が2つになり、このテストと AGENTS.md の制約を緩める必要がある。

## 帰結

- `/kb` は未知のコマンドになる。利用者は `/knowledge` に書き換える必要がある。
- `/kb` を書いた手順書、ドキュメント、覚え書きは、利用者が自分で直す。プラグインは旧名を検出しない。
- CLI の `kb` と Pi の `/knowledge` は、名前が一致しなくなる。README で両方の呼び方を示す。

## 代替案

| 代替 | 却下理由 |
|---|---|
| `/kb` を別名として残す | 表面が2つになり、コマンドは1つだけという制約を緩める必要がある。廃止の時期を決めない限り、残り続ける |
| CLI の bin 名も `knowledge` に変える | CI の `kb lint` と、エージェントの bash 呼び出しが壊れる。規約はスラッシュコマンドの名前だけを対象とする |
